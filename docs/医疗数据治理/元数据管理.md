# 元数据管理

## 核心关系与定位

- **技术 → 元数据 → 业务 → 数据资源目录**
- **元数据 = 数据资源目录 ≠ 数据资产目录**
  - **元数据**：描述数据本身，让数据 **可理解**  
  - **数据资源目录**：数据资源清单，让数据 **可找到**  
  - **数据资产目录**：将数据视为资产，让数据 **可管理、可估值、可运营**

## 元数据管理原则：应归尽归，应收尽收

- 强调 **全面性** 与 **完整性**。
- 但需明确 **元数据的边界**。

### 元数据边界的判断标准
> **是否服务于数据的发现、理解、信任、使用、管控或合规？**

### 边界的四个维度

| 维度 | 纳入范围 | 排除范围 |
|------|--------|--------|
| **业务价值维度** | 与核心业务指标、关键数据实体、监管报送相关的元数据 | 临时表、中间表、无业务含义的日志字段 |
| **生命周期维度** | 处于“活跃使用”或“受控归档”状态的数据资产 | 已明确废弃、无访问记录、无业务关联的历史垃圾数据 |
| **管理成本与收益维度** | 维护成本 ≤ 治理收益的元数据 | 成本远高于价值的低频/边缘元数据 |
| **安全与合规边界** | 涉及敏感信息的元数据（需用于分类分级） | 元数据本身不得泄露敏感内容（如真实值样例） |

## 元数据的本质

- **最常见的定义**：**“关于数据的数据”**。
- **元数据 → 目录卡片**  
  > 如果没有可靠的元数据，组织就不知道：  
  > - 拥有什么数据  
  > - 数据表示什么  
  > - 数据来自何处  
  > - 数据如何在系统中流转  
  > - 谁有权访问它  
  > - 如何保持高质量  
  >  
  > **没有元数据，组织无法将数据作为资产进行管理，甚至无法有效管理数据本身。**
- **元数据也是一种数据，应以数据管理的方式进行管理**。
- **元数据的最终目标**：支撑 **查询** 与 **分析**。

## 元数据的类型（按 ISO/IEC 11179 标准）

| 类型 | 特点 | 示例 |
|------|------|------|
| **业务元数据** | 与 **定义、描述** 相关 | 业务术语、指标口径、数据所有者 |
| **技术元数据** | 与 **物理结构** 相关 | 表名、字段类型、存储路径、ETL 脚本 |
| **操作元数据** | 与 **日志、运行** 相关 | 数据访问记录、作业执行时间、数据质量报告 |

> 注：元数据注册遵循国际标准 **ISO/IEC 11179**。

## 元数据来源（14 + n，重点）

1. **应用程序中的元数据存储库**  
2. **业务术语表**  
   - 记录组织的业务概念、术语、定义及术语间关系  
3. **商务智能（BI）工具**  
4. **配置管理工具**  
5. **数据字典**  
   - 定义单个数据库/应用/数据仓库的数据集结构与内容（非跨系统）  
6. **数据集成工具**  
7. **数据库管理和系统目录**  
   - 描述数据库内容、大小、版本、部署状态、网络/基础设施可用性等操作元数据  
8. **数据映射管理工具**  
9. **数据质量工具**  
10. **字典和目录**  
11. **事件信息工具**  
12. **建模工具和存储库**  
13. **参考数据库**  
14. **服务注册**  
15. **其他元数据存储**（n）

## 数据血缘与影响分析

- **数据血缘（Data Lineage）**：**从下往上追溯**  
  - 回答：“这个数据从哪里来？”
- **影响分析（Impact Analysis）**：**从上往下追溯**  
  - 回答：“如果修改这个字段，会影响哪些下游报表或系统？”

## 元数据管理度量指标

- 元数据存储库完整性  
- 元数据管理成熟度  
- 专职人员配备情况  
- 元数据使用情况（如查询频次、用户覆盖）  
- 业务术语活动度（如术语更新、采纳率）

### 如何理解数据管理

- **本质**：组织对数据资产进行规划、控制、提供和赋能的一系列活动，目的是确保数据在全生命周期内 **“可信、可用、可控、可增值”**。
- **目标**：
  - **可信**：数据准确、一致、完整，用户敢用、愿用  
  - **可用**：数据易于发现、理解、访问和集成  
  - **可控**：数据安全、合规、权责清晰，风险可控  
  - **可增值**：数据能支撑业务创新、智能决策、资产变现
