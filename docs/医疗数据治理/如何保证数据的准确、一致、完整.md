# 专病主题库（DWS 层）数据质量保障规范

> **说明**：本规范适用于我方在**首信公司提供的 DWD 层明细数据基础上**构建的医保专病主题库（DWS 层）。  
> 数据源（ODS/DWD）由首信负责采集、清洗与标准化，我方聚焦于 **DWS 层的主题建模、逻辑校验与指标一致性治理**，确保汇总数据可信、可解释、可复用于 ADS 层分析及商业化产品。

---

## 一、质量目标：DWS 层的核心质量维度

在依赖高质量 DWD 输入的前提下，我们在 DWS 层重点保障以下三方面质量：

| 维度 | 定义 | 我方责任范围 |
|------|------|--------------|
| **完整性** | 专病患者是否具备完整的诊疗事件链，满足分析入组要求 | ✅ 校验事件链完整性，定义“有效患者”标准 |
| **准确性** | 汇总指标是否真实反映诊疗行为，计算逻辑无误 | ✅ 验证聚合逻辑、时间顺序、业务规则 |
| **一致性** | 同一业务概念在 DWS 内各表/指标中口径统一 | ✅ 统一关键字段定义，避免歧义 |

> ⚠️ **数据局限性说明**：  
> - 本库不包含未通过医保结算的自费诊疗行为；  
> - 诊断与用药准确性依赖首信 DWD 层的原始填报质量；  
> - 患者主索引（patient_id）由首信提供，我方不做跨源融合。

---

## 二、DWS 层质量标准定义

### 1. 完整性（Completeness）

**定义**：  
专病患者在 DWS 层是否包含支撑分析所需的最小诊疗事件集合。

**示例（以 2 型糖尿病为例）**：
- **有效患者入组条件**（同时满足）：
  - 存在至少 1 条 DWD 诊断记录，ICD-10 编码为 `E11.x`（2 型糖尿病）；
  - 存在至少 1 条 DWD 药物记录，药品名称含“二甲双胍”“胰岛素”等降糖药；
  - 存在至少 1 条 DWD 检查记录，项目名称含“糖化血红蛋白”“空腹血糖”。
- **字段完整性要求**：
  - `patient_id`、`diag_date`、`drug_start_date`、`visit_id` 等关键字段不得为空；
  - 若某患者缺失随访记录，标记为 `follow_up_missing = true`，供下游按需过滤。

---

### 2. 准确性（Accuracy）

**定义**：  
DWS 层汇总指标是否符合医学逻辑、时间顺序与业务规则。

**示例**：
- **时间逻辑校验**：
  - 药物开始日期 ≥ 首次确诊日期；
  - 并发症发生日期（如糖尿病肾病 N08.3） > 糖尿病确诊日期；
- **计算逻辑校验**：
  - 年度用药总量 = Σ（单次用药数量），且单次数量 > 0；
  - 年度医保支付总额 = Σ（DWD 费用明细中的 `医保支付金额`）；
- **业务规则校验**：
  - 使用胰岛素的患者，必须存在糖尿病诊断（ICD-10 E08–E13）；
  - 同一患者同一天同一药品的单价波动 ≤ ±20%（基于 DWD 原始单价）。

---

### 3. 一致性（Consistency）

**定义**：  
DWS 层内所有表与指标对同一业务概念采用统一定义。

**示例**：
- **关键字段统一定义**：
  | 字段 | 定义 |
  |------|------|
  | `diag_date` | 首次在 DWD 诊断表中出现目标 ICD-10 编码的就诊日期 |
  | `patient_id` | 直接沿用首信 DWD 层提供的唯一患者标识 |
  | `drug_name` | 使用首信 DWD 层已标准化的药品通用名 |
- **指标口径统一**：
  - “年度并发症发生率” = （确诊后新发并发症患者数） / （总专病患者数）；
  - 所有费用类指标均基于 **医保支付金额**（不含自费），单位：元。

## 三、DWS 层质量保障机制

| 环节 | 我方实施措施 |
|------|------------|
| **建模设计** | - 在 DWS 表设计阶段明确定义每个字段的业务含义、计算逻辑、来源表<br>- 编写《专病主题库数据字典》供下游使用 |
| **数据加工** | - 在 SQL/ETL 脚本中嵌入质量校验逻辑（如 `WHERE drug_qty > 0`）<br>- 对不满足入组条件的患者打标（如 `is_valid_patient = false`） |
| **质量监控** | - 每日运行 DWS 层质量检查任务，监控：<br>  • 有效患者占比<br>  • 关键字段空值率<br>  • 逻辑矛盾记录数<br>- 异常波动自动告警至数据负责人 |
| **交付说明** | - 向 ADS 层提供《DWS 数据使用指南》，包含：<br>  • 数据覆盖范围<br>  • 已知局限性<br>  • 推荐过滤条件 |

| 主体 | 职责 |
|------|------|
| **首信公司** | 负责 ODS/DWD 层数据采集、清洗、标准化、患者主索引生成 |
| **我方（零氪）** | - 基于 DWD 构建 DWS 专病主题库<br>- 保障 DWS 层建模逻辑正确、指标口径统一<br>- 提供数据质量说明与使用建议 |
| **ADS 层团队** | 基于 DWS 输出统计报表、分析模型，需自行评估数据适用性 |
